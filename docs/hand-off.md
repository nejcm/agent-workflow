# Hand-off

`bun tender.ts open <ID | owner/repo/ID> [--tool claude|codex|t3|editor] [--exec]` moves a ticket's work to you, outside the sandbox. Every poll of `run` and `once` holds `<workspaceRoot>/.pass.lock`, and `open` and `resume` take it too, so they wait for a running poll to finish (logged) and a poll never acts on a ticket state they changed under it; neither takes `--dry-run`. It refuses an ID with no clone, then writes `<ID>.handoff` next to the clone (before the stop, so a poll never sees the window gone without it) and stops the session as for a canceled ticket: the scope is killed and the window closed, no keys are sent. It prints one line to paste into a shell (`cd '<clone>' && …`, every word quoted as needed), or runs it in the clone with `--exec` (`LINEAR_API_KEY` and `LINEAR_CLIENT_SECRET` dropped from its environment). The tool defaults to the session's own agent.

- **`claude`, `codex` on the session's own agent:** the newest transcript recorded for the clone is copied into your own store and resumed with your login and settings: `<ID>.claude/projects/<dir>/<id>.jsonl` to `$CLAUDE_CONFIG_DIR` (default `~/.claude`) `projects/<dir>/`, then `claude --resume <id>`; a Codex rollout keeps its `sessions/YYYY/MM/DD/` path under `$CODEX_HOME` (default `~/.codex`), then `codex resume <id>`. A copy already there is kept, since you may have continued it. The ticket's own config dir is never used as yours: the session could write it. A transcript reached through a symlink, or not in the expected layout, is not copied. That history was written inside the sandbox, from ticket text and repo content, and it now runs with your own login, settings and permissions; `open` says so.
- **The other agent, or no transcript:** a fresh session in the clone, told where the ticket's prompt (`<ID>.prompt.md`), the earlier transcript and `.tender/run/` are.
- **`t3`:** prints the clone's path, to add as a T3 Code project; T3 cannot resume a foreign session.
- **`editor`:** `$VISUAL`, else `$EDITOR`, run through `sh -c` as git runs it (so it may quote a path or carry flags), opened on the clone.

While `<ID>.handoff` exists the ticket is parked: no start even if it is listed Ready, no PR feedback, stall checks, findings, auto-merge, moves to or from Ready to merge, or "session ended without a PR" comment. A killed window would otherwise read as a finished session for Ready to merge. The claim (a pending one is retried as for a running session), the move to In Review once a PR exists, Done on merge (the merged-by-hand recovery of [Auto-merge](auto-merge.md#auto-merge)) and cleanup still run; a done ticket's cleanup removes `<ID>.handoff` with its other files.

`bun tender.ts resume <ID | owner/repo/ID>` gives it back: it starts a new session in the same clone, fresh config dirs as at any start, with the original prompt behind a note to read `git status`, `git log`, the PR and `.tender/run/` first, then deletes `<ID>.handoff` (after the window exists). It claims nothing and moves nothing on the tracker. It refuses a ticket that is not handed off, still has a window, or was canceled or reassigned meanwhile (`<ID>.ended`).
