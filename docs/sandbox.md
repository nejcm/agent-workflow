# Clones, sandbox and cleanup

How `tender` clones repos, isolates sessions and stops them. Setup steps are in [setup.md](setup.md).

`tender` clones each repo into `<reposRoot>/<owner>/<name>` (default `~/agent-repos`) with `gh repo clone` when `run` or `once` starts (a failed clone is logged and retried before the repo's next ticket), into `<path>.tmp-…` and renamed when done, so an interrupted clone is never used. Every command `tender` runs has a 60 s deadline (`timeout -k 5`, whole process group), so a hung `gh`, `git` or `tmux` fails that step instead of stalling polling; `gh repo clone`, the `git fetch` of `origin/<base>` before a start, the session clone and its checkout get 15 min, and so does deleting a session clone. The same fetch before merge decisions or Linear project routing runs every poll, so it keeps the 60 s. If `path` exists but is not the top of its own clone (`git rev-parse --git-common-dir` is not `<path>/.git`: an interrupted clone, or a subdirectory or linked worktree of another clone), or resolves to the same directory as another repo's `path`, the ticket is not claimed and the error is logged; `tender` never deletes it, so fix or remove it (and any stale `.tmp-…` sibling) by hand. Leave the clone there, or point `repos[].path` at another clone that is also used only by `tender`. Never point it at your working clone. Only `tender` writes it: it fetches `origin/<base>` there before each start.

Each session works in its own clone, `<workspaceRoot>/<owner>/<name>/<ID>`, made by `git clone --shared --revision refs/remotes/origin/<base>` from that base clone: it borrows the base's objects through `.git/objects/info/alternates` instead of copying them, so it is cheap at any repo size. `tender` then points its `origin` at the base's own remote URL (so `git push` works as before), sets the usual fetch refspec with `tagOpt=--no-tags` (so a fetch brings in no tags) and `origin/<base>`, and creates `agent/<ID>`, all in `<ID>.tmp`, renamed to `<ID>` only when complete (a failed step deletes it); if the base still has an `agent/<ID>` branch from an older worktree session, the new branch starts there. A borrowed object must never disappear from the base, so `tender` never prunes it (its git calls pass `maintenance.auto=false`) and sets `gc.pruneExpire=never` in the base's config, which keeps a manual `git gc` there from deleting objects too (`git gc --prune=now` and `git prune --expire=now` still do, so never run them there). Keep `reposRoot` out of `/tmp`, whose cleanup can delete those objects, and never delete packs there by hand; `git reflog expire` plus `gc` there after an upstream force-push that drops history is untested. `--local` with hardlinks was rejected because the session could write through a hardlinked object file into the base, and `--no-hardlinks` copies every object per session. Under nono the session can write only its own clone (whose `.git`, config and hooks included, nothing else uses) and read only the base's `.git/objects`; the base's refs, config, hooks and every other session are out of reach. `git push -u` records the upstream, since the session's config is its own. `tender` never runs git inside a session clone on the host once the session has started, because its config, hooks and filters are agent-controlled. At cleanup it reads what is pushed on the host, from the base clone: `git ls-remote origin HEAD 'refs/heads/*' refs/pull/<n>/head` (the PR from `<ID>.pr`, which keeps a merged PR's commits after its branch is deleted) and the base's `refs/remotes/origin/<base>`. Pushed means reachable from origin's `HEAD`, `<base>`, `agent/<ID>` or that PR head, the base's ref, or a clone `refs/remotes/origin/<name>` that origin advertises as `refs/heads/<name>` at the same SHA; any other clone `refs/remotes` ref counts for nothing. A clone with `.git/info/grafts`, `.git/commondir`, `.git/worktrees` (linked worktrees) or `.git/modules` (submodules) is kept, since the checks would not see all of it. It then runs, with `--git-dir` and `--work-tree` pinned to the clone and `core.commitGraph=false`, `git -c status.showUntrackedFiles=all status --porcelain --ignore-submodules=none`, `git rev-list --ignore-missing --all --not <pushed>` (every ref and every worktree's HEAD, detached included), `git for-each-ref refs/tags refs/stash refs/notes` and `git refs verify` (a ref with a broken name is otherwise skipped) under nono with `nono/tender-check.json`: read-only on the clone and the base's objects, no network and no credentials, so a filter or config the session planted runs with neither, and, last before deleting, scans the clone on the host for a `.git` entry (directory or file, as `--separate-git-dir` leaves) or a bare repo (a directory holding a `HEAD` file and `objects` and `refs` directories) anywhere below its top level, `node_modules` included, following no symlinks: an old-form submodule or any nested repo holds commits the checks cannot see, so one keeps the clone (remove it by hand), as does a scan that fails or passes 100,000 entries; a writer still running in the clone can race the scan and `rm`. It deletes the clone with `rm -rf --one-file-system`, which removes symlinks without following them, only if that scan finds nothing and all four git commands print nothing and exit 0: a done ticket with uncommitted, untracked or unpushed work, or any tag, stash or note (a fresh clone has none), keeps its clone, which is retried every poll until you push or delete it; each such keep reason (and the ones below) is logged once per dir while `tender` runs (again after a restart), while a failed or timed-out command is logged every poll. Files the session's own ignore rules exclude, and changes it hides from `status` in its index (`--assume-unchanged`, `--skip-worktree`), are not checked and are deleted. With `sandbox: "none"` the same checks run unsandboxed, since that agent runs unsandboxed anyway. Every command `tender` runs drops repository-local `GIT_*` variables (`git rev-parse --local-env-vars`, except `GIT_CONFIG`, `GIT_CONFIG_PARAMETERS` and `GIT_CONFIG_COUNT`, so config passed in the environment, such as a credential helper, still applies) from its environment. Like every command `tender` runs, the checks have a 60 s deadline (`timeout -k 5`, which kills the whole process group), so a planted filter that never returns cannot stall polling; on a timeout the clone is kept. A dir whose `.git` is not a directory (an older worktree session, or gone, as after an interrupted delete) is kept and logged; remove it by hand. Deleting such a dir when it looks empty was tried and dropped: non-UTF-8 names, a write between scan and `rm`, and bind mounts each lost data.

`tender`'s own `git` calls also pass `-c` overrides (`core.hooksPath`, `core.fsmonitor`, `core.alternateRefsCommand`, `maintenance.auto`, and the `ext`, `file` and `git://` transports) as a second layer; only the local copy that creates a session clone re-allows `file`. Because of the `file` override, the clone's `origin` must be an HTTPS or SSH URL; a clone of a local path fails at `git fetch` (`transport 'file' not allowed`).

GitHub: under nono the session's `GH_TOKEN` is a phantom that nono's proxy swaps for your `gh` token only on `GET /repos/**` and `GET /user`; every other method or path (any write, `/graphql`, so every `gh pr` and `gh issue` command) reaches GitHub with the phantom and fails with HTTP 401. `tender` opens the PR from the agent's PR file (see [How it works](lifecycle.md#pr-file)). `git push` goes through a separate credential with no path rules, so the session can still push to any branch of any repo your login can write, `baseBranch` included: branch protection stays the boundary. Running sessions keep the rules their profile had when they started. With `sandbox: "none"` the session uses your own `gh` login with all its rights; the VM is the boundary.

Commit author: the launch script exports `GIT_AUTHOR_NAME="Tender Claude (<model>)"` (`Tender Codex`, no parentheses without a model) and `GIT_AUTHOR_EMAIL=tender@tender.invalid`, in both sandbox modes (both profiles pass them in `allow_vars`). The committer stays your own git identity, so GitHub shows tender as author and you as committer. `.invalid` can never be verified, so the address links to no GitHub account. It is provenance, not proof: the agent can unset the variables or set `user.*` in its clone, and a ruleset that restricts author emails can reject these commits.

Unix sockets: Landlock's file rules do not cover `connect()` to a socket, so both profiles set `linux.af_unix_mediation: "pathname"`. Without it, a session could reach your tmux server (`tmux new-window <cmd>` runs on the host), the systemd user manager, D-Bus, gpg/ssh agents, Hyprland and other Claude sessions under `$XDG_RUNTIME_DIR/cc-socks`. The profiles add no host sockets; nono's inherited `default` profile allows connecting to the systemd userdb sockets in `/run/systemd/userdb` (`io.systemd.Multiplexer`, `DropIn`, `NameServiceSwitch`, `DynamicUser`), which answer user and group lookups. The launcher adds `--allow-unix-socket-subtree-bind` for the clone and for the session's temp dir (below), so a session can bind and connect sockets only there; sockets elsewhere (`/tmp` included) and in the abstract namespace fail with `EACCES`. `gh` cannot read `~/.config/gh` in the sandbox and exits if it cannot load its config, so the launcher sets `GH_CONFIG_DIR=<clone>.gh`, a path that never exists: `gh` runs on its defaults with nono's `GH_TOKEN`, and your `gh` config (aliases, `git_protocol`, extensions) does not apply in sessions. gh, git and the GitHub credentials go through nono's TCP proxy, and Codex runs with `--no-daemon`, so neither needs a socket. Claude's inter-session messaging socket (`cc-socks/<pid>.sock`) is denied, and sessions run without it.

Templates: both profiles grant read on `~/.claude-tender`'s `settings.json`, `CLAUDE.md`, `AGENTS.md`, `skills` and `plugins` and `~/.codex-tender`'s `AGENTS.md` and `skills`, the targets of the links in each `<ID>.claude` and `<ID>.codex`; without them a session sees the links but not your instructions or skills. nono resolves each path, so a template entry that is itself a link grants its target, and skips one that does not exist. Both also deny the templates' `config.toml`, `hooks.json`, `auth.json`, `.credentials.json` and `oauth-token`, so a `skills` link into a template makes nono refuse to start. Everything else in the templates and your home stays unreadable unless a template's `skills` entry is itself a link into it (nono 0.81.0 does not catch a grant that resolves exactly onto a credential dir it denies), so keep it a plain directory.

Terminals: both profiles exclude nono's `system_read_linux_core` and `system_write_linux` groups, which grant `/dev/pts`, and re-add their other paths. A session reaches its terminal through `/dev/tty` and the pty nono gives it, but cannot open any other `/dev/pts/N`, so it cannot read what you type in another pane or shell, or write escape sequences into it. `/dev/ptmx` is denied too, so a session cannot allocate a pty of its own: Codex's `exec_command` with `tty: true` fails, and plain (pipe) commands, which Claude Code and Codex use by default, are unaffected.

Temp dir: each session gets its own `<ID>.tmpdir` next to its clone, emptied and recreated (mode 700) by `tender` on the host at every start and deleted at cleanup. The launcher exports it as `TMPDIR`, `TMP`, `TEMP` and Claude's `CLAUDE_CODE_TMPDIR`, so `mktemp`, `os.tmpdir()`, Python's `tempfile` and tools that follow them, socket-creating test suites included, land there. Under nono it also holds the session's `XDG_CACHE_HOME`, `<ID>.tmpdir/cache`, so Claude's cache and logs (`claude-cli-nodejs`) and other tools' caches are per session: no profile grants your `~/.cache`, which your own Claude Code also uses. It is a sidecar rather than a dir in the clone so temp files never show in `git status` or block cleanup. Both profiles exclude nono's `system_write_linux` group, the only one granting `/tmp`, and re-grant its `/dev` and `/proc/self/fd` entries except `/dev/pts`, so a session can no longer write the `/tmp` it shared with your host and other sessions; a tool that hardcodes `/tmp` fails (reading there was already denied). A Unix socket path is at most 107 bytes: with `~/agent-ws/nejcm/agent-workflow` and an ID like `ENG-12345` the temp dir is 57 bytes, which leaves 50 for the socket's own path, so a long `workspaceRoot`, owner or repo name can make a test suite's socket fail with `AF_UNIX path too long`; keep `workspaceRoot` short. A start logs a warning (and still starts) when the temp dir leaves under 22 bytes, the length of tsx's `/tsx-<uid>/<pid>.pipe`.

Stopping: the launcher runs each session in its own systemd user scope, `tender-<hash>:<owner>:<name>:<ID>.scope`, where `<hash>` is the first 8 hex chars of the SHA-256 of `workspaceRoot` (`systemd-run --user --scope --collect`, with or without nono, plus `--expand-environment=no` where systemd has it (254+) so it leaves `$` in the prompt and hooks alone), because `tmux kill-window` only hangs up the pane: a session that ignores `SIGHUP` or `setsid`s a child keeps running, with its credentials and network. Every stop (done, canceled, reassigned) first runs `systemctl --user kill --signal=KILL` on that scope, which kills every process in it, then kills the window; a scope that is gone is fine. A start kills any scope left under the ticket's name first, and fails (logged, ticket not claimed, retried next poll) if the user manager cannot be reached, so `tender` never starts a session it could not stop. Each pass, before any start, also kills every scope of this workspace that holds none of its tmux session's pane processes (an orphan, whatever its ticket's state; renaming a window does not count), and kills nothing if the panes cannot be listed. The sandbox cannot reach the user manager's sockets, so a session cannot leave its scope. `systemctl --user list-units 'tender-*.scope'` lists them; a session started before scopes existed has none and is stopped by kill-window alone.

## Ports and services

A task type with `needs: { ports: n, compose?: <file> }` gets `n` loopback TCP ports, in `TENDER_PORT_0`… (nono's profiles pass `TENDER_PORT_*` through), each granted with nono's `--open-port` (listen and connect). nono grants a port, not an address: the sandbox can also reach that port on any other host. The grants need Landlock ABI 4 (Linux 6.7) or newer; on an older kernel nothing that needs ports starts (the session is not started), and `tender check` reports it. Ports come from 20000–29999, below Linux's ephemeral range, allocated under the pass lock: none that another session (`<ID>.needs`) of the workspace holds or that something listens on now; one that cannot be read stops the allocation. A fresh start gets new ports and a resume keeps its own.

`compose` names a Compose file in the repo, which `tender` runs through Docker, outside the sandbox, never from a session clone: it extracts the base commit (`git archive`) into `<ID>.compose/tree` and runs `docker compose` there, from `/` with only `PATH`, `HOME`, the Docker connection variables and the ports in the environment, so no `.env` or setting from the PR's head applies. `docker compose config` must show every published port on `127.0.0.1` and one of the assigned ports (write `127.0.0.1:${TENDER_PORT_1}:5432`), and no service with `network_mode: host`; otherwise nothing starts. The file may not use `include` or `extends` with a `file`, and a `.env` in the tree is ignored (`--env-file /dev/null`), so only the declared file, a critical path, shapes what runs. Then `up -d --wait`. The Docker daemon is host root, so every declared compose file is a [critical path](auto-merge.md#auto-merge). The project is named `<scope>-<id>-<hash>`, recorded with what it needs in `job.json` before anything starts, and taken down by name with `down -v` (containers, networks and volumes): before each `up`, when the ticket is done or canceled (a failed `down` keeps everything and is retried each poll). A session's services start in its launcher, before the agent, so the poll never waits on them; if they fail, the window ends and the error is the ended notice. Prefer named volumes to bind mounts: a container can leave root-owned files that `tender` cannot delete, which keeps the dir.

Checked live (nono 0.81.0, Claude 2.1.3xx, Codex 0.167–0.171, Nov 2026):
- Session clone, base outside `/tmp` with a local bare remote: commit, fetch, rebase, `push -u` (upstream recorded), `git config` and `git gc` work; writing the base's `objects/`, `refs/`, `logs/`, `.git` or worktree, and reading its config, fail; the session's `gc` packs only its own objects and `fsck --connectivity-only` passes. Cleanup's `rm -rf --one-file-system` never follows symlinks (link targets survive).
- Temp dir under `/dev/shm`: `mktemp`, Python `tempfile`, bun `os.tmpdir()` use it; a Unix socket bound and connected there works; writing `/tmp`, binding `/tmp/*.sock` and connecting the host tmux socket fail; git, `gh api /user` (with `GH_CONFIG_DIR` in the temp dir), `bun install` and `bun test` work. Socket paths are limited to 108 bytes.
- Unix sockets: before `af_unix_mediation`, a session could connect to the tmux server, `systemd/private`, `bus`, gnupg, keyring, Hyprland, Wayland, X11 and live Claude `cc-socks`; now all return `EACCES`, and real Claude and Codex sessions (TUI, model turn, shell tool, git through the proxy, `gh api` REST reads) work unchanged.
- Claude: `claude -p` starts under the profile, creates `claude-<uid>/` in the temp dir and reaches the API; the seeded trust key starts a fresh clone with no dialog (without it Claude shows the trust prompt). Its resolver is `CLAUDE_CODE_TMPDIR ?? os.tmpdir()` while its bash sandbox env uses `CLAUDE_CODE_TMPDIR || CLAUDE_TMPDIR || "/tmp/claude"`, hence `CLAUDE_CODE_TMPDIR` is kept and pointed at the temp dir.
- Codex: `std::env::temp_dir()` reads `TMPDIR`, and its arg0 helpers go in `$CODEX_HOME/tmp` (already granted). nono puts `.nono-<hash>.json`, `nono-browser-*` and `nono-url-sock-*/supervisor.sock` in `TMPDIR`; with a 94-byte `TMPDIR` it skipped them and the session still ran.
- Ports and services (nono 0.81.0, Landlock ABI 10, Docker Compose): `TENDER_PORT_*` reaches a session under `nono/tender-claude.json`; a session `up` from the base tree, its teardown and a mapping with an unset port (rejected before `up`) behaved as above.

Codex under nono runs with `--no-daemon` (required on Linux), so sandboxed Codex sessions show in the app history but cannot be live-steered; with `sandbox: "none"` they can.
